# DSP-X8s 網頁調音器 設計規格

日期：2026-09-29
狀態：待使用者審閱

## 1. 目標

為 Yiye lang DSP-X8s 車用 DSP 做一個手機瀏覽器可用的調音網頁，透過藍牙直接控制機器，並可安裝為 PWA 離線執行。

使用者指定的四個功能：

1. 藍牙連線，連上後立即把機器目前的設定全部讀回來顯示。
2. 調聲音：主音量、各聲道音量、靜音、相位、延時、輸入源。
3. EQ：8 個輸出聲道各自獨立的 31 段參數 EQ，可調頻率、增益、Q 值，附頻率響應曲線。
4. 8 組模式：切換與儲存。

## 2. 非目標（本期不做）

- 分頻（高通、低通）、濾波器類型切換、壓縮限幅、輸入路由矩陣。編碼未知，等第一階段讀出真機資料後再決定。
- 機器內的模式名稱讀寫。指令存在但資料格式未知。
- USB 音樂播放器。
- 原廠 App 使用的 4 段快速 EQ 層（IIR100 到 IIR107）。原廠 App 每次連線都會覆寫它，網頁只顯示不修改。
- iPhone 的 Safari 原生支援。Safari 沒有 Web Bluetooth，iPhone 使用者需改用 Bluefy 瀏覽器開啟本網頁。

## 3. 使用環境與限制

- 目標裝置：Android 手機的 Chrome 或 Edge。開發與測試也可用 Windows 上的 Chrome。
- 必須以 HTTPS 提供（例如 GitHub Pages），開發時 localhost 可用。
- 藍牙連線必須由使用者點擊觸發。
- 離線：所有資源由 Service Worker 預先快取，第一次載入後不需要網路。藍牙本身不需要網路。
- 瀏覽器在背景分頁會節流計時器，佇列必須事件驅動，不能依賴固定毫秒計時。

## 4. 架構

四層，每層只依賴下一層，全部用純 ES modules，不用框架與建置工具。

| 層 | 內容 | 相依 |
| --- | --- | --- |
| protocol | CRC-16、封包編解碼、數值編碼、位址表。純函式。 | 無 |
| transport | Transport 介面。BleTransport 用 Web Bluetooth。FakeDevice 在瀏覽器與測試中模擬機器。 | protocol |
| core | Queue（送出、等待確認、重送、逾時）、Store（1613 個暫存器的快取與事件）、Device（連線流程、整機讀取、心跳、高階讀寫 API）。 | protocol, transport |
| ui | 四個分頁與共用元件。只透過 Device 與 Store 存取資料。 | core |

## 5. 協定規格

以下數值全部來自反編譯的原廠小程序，除另有標註者外都已被原廠 App 實際使用。

### 5.1 BLE

- Service 0000ae00-0000-1000-8000-00805f9b34fb
- Write characteristic 0000ae01-0000-1000-8000-00805f9b34fb
- Notify characteristic 0000ae02-0000-1000-8000-00805f9b34fb
- 掃描：先用 service 過濾，找不到時改用接受所有裝置並把 ae00 列入 optionalServices。
- 寫入以 20 位元組分段，每段 writeValue 完成後才送下一段。
- 通知會分段到達，需重組。

### 5.2 封包格式

```
[0x80][LEN][CMD][DATA ...][CRC_HI][CRC_LO]
```

- LEN = 封包總長 − 2 = DATA 長度 + 3。上限 250。
- CRC-16：初始值 0xFFFF，多項式 0xA001（反向），無最終異或，即 CRC-16/MODBUS。計算範圍為 0x80 起到 DATA 結尾。輸出高位元組在前。
- 重組演算法：在緩衝區中掃描 0x80，檢查 LEN 不超過 250 且資料足夠，驗證 CRC，失敗則丟棄一個位元組繼續掃描。

### 5.3 指令

| CMD | 名稱 | DATA | 回應 |
| --- | --- | --- | --- |
| 0x00 | 檢查客戶代碼 | 00 00 | 2 位元組代碼，預期 4006（0x0FA6） |
| 0x01 | 呼叫模式 | 1 位元組模式號 1 到 8 | 同指令回應，帶模式號 |
| 0x03 | 寫入暫存器 | 重複 ADDR_HI ADDR_LO VAL_HI VAL_LO，原廠每包最多 3 組 | 原封不動回傳整個封包 |
| 0x06 | 讀取暫存器 | 重複 ADDR_HI ADDR_LO，原廠每包最多 14 個 | 重複 ADDR VAL 四位元組一組 |
| 0x11 | 儲存模式 | 1 位元組模式號 | 同指令回應 |
| 0x61 | 區段讀取 | START_HI START_LO，原廠每次 100 個 | START 加上連續的 VAL 各 2 位元組 |
| 0x04 / 0x10 | 讀寫模式名稱 | 未知 | 本期不用 |
| 0x71 / 0x72 | USB 檔案通道 | 不用 | 收到 0x71 時直接忽略 |

回應配對規則：

- 寫入：回應與送出封包逐位元組完全相同。
- 讀取與區段讀取：CMD 相同且第一個位址相同。
- 呼叫與儲存模式：CMD 相同。

區段讀取的回應數量以實際封包長度計算，不採用原廠程式碼中的 len AND 0xFA 遮罩，那很可能是原廠的錯誤。

### 5.4 數值編碼

| 欄位 | 編碼 | 解碼 |
| --- | --- | --- |
| 增益 dB | raw = round(10 × dB) + 500 | dB = (raw − 500) / 10 |
| 頻率 Hz | Hz < 100：raw = (10 × Hz) OR 0x8000；否則 raw = Hz | bit15 為 1：(raw AND 0x7FFF) / 10；否則 raw |
| Q 值 | raw = round(100 × Q) | Q = raw / 100 |
| 音量與相位 | raw = vol + (flag ? 500 : 0) | vol = raw ≥ 500 ? raw − 500 : raw，flag = raw ≥ 500 |
| 延時 | raw = 微秒，範圍 0 到 20000 | 毫秒 = raw / 1000；公分 = raw × 0.0346 |
| 靜音 | 1 = 靜音，0 = 正常 | |

備註：

- 原廠 4 段層的 Q 值另外除以 QRate = 7.6 / 2.4。31 段層是否也套用 QRate 未知，第一階段讀取後判斷：未觸碰的頻段若 Q 原始值約 100 則不套用，約 32 則套用。
- 主音量：原廠旋鈕 0 到 60，寫入 raw = 500 + 40 + 旋鈕值，同一個值寫到 MIX11_1 到 MIX11_8。flag 在此永遠為 1，意義不明，本專案沿用。
- 相位：原廠在 MIX41_k_1（第 k 聲道對輸入 1 的路由增益）上切換 flag。假設 raw ≥ 500 為反相，需真機確認。
- 延時：原廠 UI 以 48 kHz 取樣點為步進，0 到 960 點對應 0 到 20 ms。
- 增益範圍：原廠限制 −12 到 +12 dB，0.1 dB 一格。實際上限未知，本期沿用。

### 5.5 位址表

共 1679 個位址（0 到 1678）。本專案的讀取範圍為 0 到 1612（ID_APP_END，等於 MP23X 機型長度），不讀 1613 以後的 CONTROL 區。

模式區（0 到 1225，隨模式儲存與呼叫）：

| 位址 | 內容 |
| --- | --- |
| 0 | 機型 |
| 1 到 11 | MUTE_1 到 MUTE_11。原廠用 MUTE_2 到 MUTE_9 對應輸出 CH1 到 CH8 |
| 12 到 25 | MIX11_1 到 MIX11_14。原廠用 1 到 8 為各聲道主音量 |
| 26 到 57 | MIX41_k_i，8 輸出 × 4 輸入路由增益。原廠只用 MIX41_k_1 切相位 |
| 58 到 72 | Switch21_1 到 15。Switch21_2 為 0 表示 EQ 旁通，1 表示 EQ 啟用（原廠只讀） |
| 73 到 81 | Delay1 到 Delay9。原廠用 1 到 8 |
| 82 到 137 | 壓縮器 3 到 10，各 7 個參數 |
| 138 到 1225 | 8 聲道濾波器區，每聲道 136 個位址 |
| 1226 | MODE_END |

每聲道濾波器區的配置，base = 138 + (ch − 1) × 136，ch 為 1 到 8：

| 相對位址 | 內容 |
| --- | --- |
| base + 0 到 7 | 2 個濾波器，各 TYPE、F、G、Q。推測為分頻用，本期不寫 |
| base + 8 + 4 × b + 0 | 第 b 段（b 為 0 到 31）TYPE，本期不寫 |
| base + 8 + 4 × b + 1 | 第 b 段 F |
| base + 8 + 4 × b + 2 | 第 b 段 G |
| base + 8 + 4 × b + 3 | 第 b 段 Q |

共 32 個 EQ 欄位，機殼標示 31EQ。第 32 欄位的內容以第一階段讀取結果決定是否顯示。

狀態區（1227 以後，不隨模式）：

| 位址 | 內容 |
| --- | --- |
| 1234 (M0_8) | 輸入源，寫入用。2 = 藍牙，3 = 高電平，4 = AUX，7 = USB |
| 1242 (M0_16) | 目前模式號 1 到 8 |
| 1248 (M0_22) | 目前輸入源，讀取時取低 4 位元 |
| 1252 到 1571 | IIR100 到 IIR107，原廠 4 段快速 EQ 層，本期只讀 |
| 1572 到 1603 | 各輸入源的各聲道音量，本期只讀 |
| 1588 (USB_L_VOL) | 心跳讀取項之一 |

原廠心跳讀取 M0_22、M0_16、USB_L_VOL 三個位址。

## 6. 連線流程

1. 使用者點擊「連線」。呼叫 requestDevice，連 GATT，取得兩個 characteristic，開啟通知。
2. 送出檢查客戶代碼。回應為 4006 時進入正常模式。不符時顯示警告，進入唯讀模式，所有寫入按鈕停用。
3. 整機讀取：用區段讀取每次 100 個，從 0 到 1600 共 17 個請求，顯示進度。任一請求失敗三次則改用一般讀取每包 14 個位址重試該區段。
4. 讀取完成後把結果寫入 Store，四個分頁依 Store 更新畫面。同時自動把這次讀取結果以時間戳存到瀏覽器本地，作為還原點。
5. 啟動心跳：每 1000 ms 讀取 M0_22、M0_16、USB_L_VOL。心跳結果若顯示模式號改變（例如使用者用機器實體按鍵切換），自動重新整機讀取。
6. 斷線：GATT 斷線事件或連續逾時，UI 回到未連線狀態，保留最後一次讀到的資料供檢視。
7. 若瀏覽器支援 getDevices，下次開啟時列出上次配對過的裝置供一鍵重連；不支援則要求重新選擇。

## 7. 功能規格

五個底部分頁：藍牙、聲音、EQ、模式、日誌。頂部常駐狀態列顯示連線狀態、目前模式、目前輸入源。

### 7.1 藍牙分頁

- 連線與斷線按鈕，連線狀態、裝置名稱、客戶代碼。
- 整機讀取進度條與「重新讀取」按鈕。
- 備份：匯出目前 1613 個暫存器為 JSON 檔（含時間戳、模式號）。
- 還原點列表：顯示本地保存的讀取快照，可匯出、刪除。本期不提供整機寫回，避免未知欄位誤寫。
- 進階區（預設收合）：原始暫存器表格，可依位址範圍檢視十進位與十六進位值，可搜尋位址名稱。第一階段用它判讀未知編碼。
- 第一階段測試按鈕：對 CH1 指定頻段寫入一個增益值，寫入後讀回並顯示比對結果。第二階段完成後移到進階區。

### 7.2 聲音分頁

- 主音量旋鈕或滑桿 0 到 60，同時寫 MIX11_1 到 MIX11_8。
- 「各聲道獨立」開關：打開後顯示 8 支聲道音量滑桿，各自寫入對應的 MIX11_k。
- 8 個聲道各一列：名稱（CH1 到 CH8，可自訂名稱存在本地）、靜音、相位、延時。
- 延時以毫秒與公分同時顯示，可用滑桿或加減按鈕以 1 個取樣點步進，範圍 0 到 20 ms。
- 輸入源四選一：藍牙、高電平、AUX、USB。寫 M0_8，顯示以 M0_22 為準。
- 靜音寫 MUTE_(k+1)，相位在 MIX41_k_1 切換 flag，保留原音量值。

### 7.3 EQ 分頁

- 聲道選擇：CH1 到 CH8 八個按鈕。
- 連動群組：可把多個聲道勾成一組，對該組任何一個聲道的變更同步寫到組內所有聲道的相同頻段。預設提供三個快速群組：前（CH1、CH2）、後（CH3、CH4）、全部。群組設定存在本地。
- 頻率響應曲線：以 canvas 繪製目前聲道 31 段的合成響應，20 Hz 到 20 kHz 對數軸，−15 到 +15 dB。以 48 kHz 取樣率用峰值型二階濾波器公式計算。曲線上每一段以可拖曳的點表示，拖曳點改變增益，橫向拖曳改變頻率。
- 頻段列表：31 列，每列顯示頻率、增益、Q 值三個可調欄位。頻率與 Q 值從機器內建表格選取（頻率表 19.7 Hz 到 20.6 kHz 共 364 級，Q 表 0.4 到 128 共 101 級），增益 −12 到 +12 dB 步進 0.1。
- 單段重置、整聲道重置（增益全部歸零，不動頻率與 Q）。
- 複製聲道：把目前聲道的 31 段複製到選定的其他聲道。
- 旁通指示：以 Switch21_2 顯示 EQ 啟用或旁通，本期只顯示。
- 本地預設：把目前聲道或全部 8 聲道的 EQ 存成命名預設，可載入、刪除、匯出、匯入 JSON。載入時逐段寫入機器。
- 寫入策略：拖曳中每 50 ms 最多送一次，同一位址只保留最新值。拖曳停止 300 ms 後讀回本次觸碰過的位址並比對，不符的頻段標紅並顯示機器實際值。
- 本期只寫 F、G、Q，不寫 TYPE。若讀取結果顯示某段 TYPE 為 0 或 F 為 0，該段標示為「機器未啟用」並停用編輯，避免對關閉中的濾波器寫值造成不可預期結果。此規則在第一階段確認 TYPE 預設值後可能調整。

### 7.4 模式分頁

- 8 個大按鈕，目前模式高亮（來源 M0_16）。
- 點擊其他模式：送呼叫模式指令，收到回應後等待 1200 ms，再整機讀取更新畫面。等待期間鎖定所有分頁的寫入。
- 「儲存到模式 N」按鈕：彈出確認對話框，說明將覆寫該槽，確認後送儲存模式指令。成功後顯示提示。
- 模式名稱：本地自訂，存在瀏覽器，不寫入機器。
- 模式比較：顯示目前運作中參數與最後一次讀取快照的差異數量，提醒使用者有未儲存變更。

### 7.5 日誌分頁

用途：真機測試時把所有發生的事記在網頁上，使用者一鍵複製貼給開發者。這是第一階段回報的唯一管道，所以要能在沒有電腦、沒有開發者工具的手機上獨立運作。

記錄內容，每行一筆，格式為「相對時間 ms、類別、內容」：

- INFO：瀏覽器與作業系統字串、是否支援 Web Bluetooth、是否在 Bluefy 內、連線開始與結束、找到的 service 與 characteristic、客戶代碼結果、整機讀取每一區段的結果與耗時。
- TX / RX：每個送出與收到的封包，十六進位原始位元組加上解碼摘要。解碼摘要包含指令名稱、位址名稱、原始值與解碼後的值。例如 `TX 03 寫入 CH1 EQ3 G raw=560 (+6.0 dB)`。
- WARN：逾時重送、CRC 錯誤與丟棄的位元組、讀回比對不符。
- ERR：斷線、GATT 例外、未預期的回應。

報告摘要：整機讀取完成後，以及每次寫入測試完成後，自動產生一段以 `===== 報告摘要 =====` 包起來的純文字，內容固定包含：

1. 瀏覽器字串、裝置名稱、客戶代碼。
2. 整機讀取是否完整、耗時、失敗區段。
3. CH1 濾波器區 base + 0 到 7 的 8 個原始值。
4. CH1 前 3 段與第 32 段的 TYPE、F、G、Q 原始值與解碼值。
5. 8 個聲道第 1 段的 Q 原始值，以及據此推斷是否套用 QRate。
6. MUTE_1 到 11、MIX11_1 到 8、MIX41_k_1、Switch21_1 到 15、Delay1 到 9、M0_1 到 24 的原始值。
7. 寫入測試：送出的位址與值、讀回的值、是否一致、耗時。

使用者只需複製這一段就足夠開發者判讀。

操作：

- 「複製全部」與「複製報告摘要」：優先用 navigator.clipboard，失敗時把內容放進全選的 textarea 讓使用者長按複製。
- 「分享」：支援 Web Share API 時以文字或 .txt 檔分享到其他 App，方便從手機傳到電腦。
- 「匯出 .txt」、「清除」。
- 篩選：全部、重點（INFO、WARN、ERR 與報告摘要）、只看封包。
- 自動捲到底部，可暫停。

保存：日誌同時寫入 IndexedDB，每 50 行或每 2 秒批次寫一次。網頁重開時可從「上次日誌」載回，避免手機瀏覽器崩潰後資料遺失。記憶體中最多保留 20000 行，超過時丟棄最舊的並在第一行標示。

## 8. 狀態與資料流

- Store 持有 Uint16Array(1613) 與每個位址的狀態：unknown、confirmed、pending、mismatch。提供 get(addr)、subscribe(range, fn)。
- 使用者操作 → UI 呼叫 device.write([{addr, val}, ...]) → Store 標記 pending 並立即更新畫面 → Queue 送出 → 收到回應標記 confirmed → 讀回比對後標記 confirmed 或 mismatch。
- 所有從機器讀到的值都先經 Store，UI 不直接接觸封包。
- Logger 是獨立的單例，transport、Queue、Device 各自呼叫它記錄事件與封包。UI 的日誌分頁訂閱它。Logger 依賴 protocol 層的位址名稱表來做解碼摘要，不依賴 UI。
- 本地保存（快照、預設、群組、名稱）使用 IndexedDB，讀寫失敗時退為記憶體，不影響主要功能。

## 9. 錯誤處理

| 情況 | 行為 |
| --- | --- |
| 找不到裝置或使用者取消選擇 | 顯示提示，停留在藍牙分頁 |
| 客戶代碼不符 | 警告，唯讀模式 |
| 單一封包逾時 1700 ms | 重送，最多 3 次 |
| 連續逾時或 GATT 斷線 | 標記斷線，停止心跳，保留資料 |
| 整機讀取部分失敗 | 改用一般讀取重試該區段，仍失敗則標示該區段 unknown，允許繼續但相關控制項停用 |
| 讀回比對不符 | 該控制項標紅，顯示機器實際值，提供「以機器為準」按鈕 |
| CRC 錯誤 | 丟棄該位元組繼續掃描，累計顯示在進階區 |

## 10. PWA

**2026-09-30 變更：使用者決定不做離線快取。** iPhone 的 Bluefy 無法執行 Service Worker，且快取優先策略在該環境卡住不能用。不使用 Service Worker，網頁每次都從網路載入。以下原始內容保留供參考。

- manifest.webmanifest：名稱、圖示、display standalone、直式方向、主題色。
- sw.js：安裝時預先快取全部靜態檔案，快取名稱含版本號，啟用時清除舊版本。策略為快取優先。偵測到新版本時在畫面上提示重新載入。
- 沒有任何外部 CDN 相依，所有資源都在專案內。
- 離線就緒指示：Service Worker 預先快取全部完成後，藍牙分頁頂端顯示「已可離線使用，版本 N」。快取未完成或失敗時顯示「尚未可離線使用」與原因。使用者離開網路前以此確認。
- 啟動時呼叫 navigator.storage.persist() 要求持久儲存，降低瀏覽器在空間不足時清除快取的機率。已安裝到主畫面的 PWA 另受瀏覽器保護。
- 內建「如何離線使用」說明頁，分 Android Chrome 與 iPhone Bluefy 兩段，列出安裝到主畫面的步驟與飛航模式自我測試步驟。
- 部署：靜態檔案放到提供 HTTPS 的免費靜態主機（GitHub Pages 或 Netlify）。使用者在有網路時開啟一次網址並安裝到主畫面，之後離線從主畫面圖示啟動。
- iPhone Bluefy 內的 Service Worker 支援未經證實。第一階段真機測試時一併驗證：載入後開飛航模式重開，能開則離線可用，不能則改為每次使用時以行動數據載入，或改走 Capacitor 包裝。

## 11. 測試策略

- protocol 層：Node 內建 node:test。測 CRC 已知向量、封包組裝與解析、分段重組、四種數值編碼的往返、位址表換算（聲道與頻段轉位址及反向）、區段讀取回應解析。
- core 層：以 FakeDevice 為 transport 測 Queue 的確認配對、重送、逾時、同位址合併、整機讀取流程、心跳觸發重新讀取。
- FakeDevice 同時在瀏覽器以 ?sim=1 啟用，讓 UI 不接機器也能操作與展示。它實作代碼回應、讀寫回聲、區段讀取、8 槽模式的呼叫與儲存。
- UI 層以手動測試為主，第一階段真機驗證清單見第 13 節。

## 13. 階段與真機驗證

### 第一階段

交付：藍牙分頁完整、日誌分頁完整（含報告摘要）、聲音分頁的主音量與模式分頁的顯示、進階暫存器表、單頻段寫入測試、FakeDevice、protocol 與 core 測試。

真機驗證清單（使用者執行，Android Chrome、Windows Chrome 或 iPhone 上的 Bluefy 皆可）：

1. 連線成功，客戶代碼顯示 4006。
2. 整機讀取完成，匯出 JSON 存檔。
3. 音量先調低，用測試按鈕對 CH1 某一段寫入 +6 dB，聽是否有變化。
4. 切到日誌分頁，按「複製報告摘要」，貼給開發者。若複製失敗改用「分享」或「匯出 .txt」。
5. 開發者依報告摘要判定：31 段區域是否可寫、Q 值是否套用 QRate、TYPE 預設值、第 32 欄位是否有效、相位 flag 方向。
6. 據此定案第二階段的 TYPE 處理規則與 Q 值換算。

### 第二階段

交付：EQ 分頁完整、聲音分頁其餘功能、模式呼叫與儲存、本地預設、PWA 離線、Service Worker。

### 之後

分頻、濾波器類型、壓縮器、模式名稱、整機寫回還原。

## 14. 假設與風險

- 主要目標為 Android Chrome。iPhone 以 Bluefy 瀏覽器為第二目標，兩者共用同一份程式碼。若之後需要正式 iOS App，以 Capacitor 包裝並新增原生藍牙的 Transport 實作，其他層不變。
- 假設 31 段區域可透過藍牙寫入。若第一階段證實不可寫，EQ 功能需改為透過 PC USB 連接埠，本規格作廢重議。
- 假設 31 段層的 TYPE 預設為峰值型且已啟用。若未啟用而 TYPE 編碼又未知，第二階段的 EQ 只能對已啟用的頻段操作。
- 相位 flag 方向、主音量 flag 意義、增益上限皆為推測，第一階段驗證。
- 寫錯值可能破壞已儲存的調音。緩解措施：連線即自動快照、儲存模式需確認、本期不做整機寫回。
